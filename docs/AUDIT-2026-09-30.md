## Additional Findings

### P2: Paid history contract exceeds implemented behavior

`static/openapi.json` advertises inclusive `from`/`to` date filters. `netlify/functions/labor-stats-history.mjs` exposes query parameters through its SDK adapter, but loads and returns the whole history JSON without filtering observations. `scripts/refresh_labor_stats.py` always emits `revisions: []`; it does not preserve previous data vintages or calculate revisions despite the route's description mentioning revisions.

The production endpoint correctly challenges an unpaid GET with HTTP 402, x402 v2, Base mainnet USDC, and amount `10000` (0.01 USDC). That confirms challenge generation, not successful payment settlement or paid fulfillment. The deployed history artifact is stale. Align the advertised features with implementation and verify payment/fulfillment before treating the paid product as fully verified.

### P2: Release-calendar metadata cannot update automatically

The live dashboard says its next employment release is July 2, even though its snapshot is July 21. The refresher copies `next_employment_release` and `next_jolts_release` from existing JSON unchanged. Fixing the workflow alone will leave these dates stale. Populate them from maintained release-calendar data or remove the unsupported upcoming-date claims.

### P2: Content validation does not establish factual freshness

All 80 audited articles pass the existing structural validator and can be formatted by the X script. However, validation only checks format and minimum link count, not URL validity, publication dates, claim support, or previous-story repetition. The generator permits optional web search (`tool_choice: auto`) and does not inspect whether search actually occurred.

Example: the September 3 brief supports a specific payroll benchmark claim with the generic BLS homepage. Several August sources recur on three different days. This is a quality-control gap, not proof every associated claim is false. Article-by-article factual verification and exhaustive external-link checking were outside this operational audit.

### P3: Presentation and documentation drift

- The dashboard describes paid history as a future/planned endpoint even though production issues real payment challenges.
- The page head references `/favicon.ico`, which returns 404; `/favicon.svg` exists and returns 200.
- The local README and session handoff describe an older checkout; remote handoff text also contains historical setup notes that conflict with its later production-launch entries.
- Actions log Node 20 deprecation warnings for checkout/setup-python. They are not the cause of the observed failures.
